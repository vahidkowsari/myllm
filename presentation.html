01 the core idea

The whole thing is one idea

Given some text, guess the next character.
🔁

That's literally it

Show it "To be or not to b" → it predicts "e". Repeat that forever and it writes whole plays.

⚖️

Two phases

Train — practice guessing on real text until it's good.
Sample — let it guess, append, repeat → new text.

Everything else is just how it makes that guess well.

03 step one

1Tokenizer — text becomes numbers

The model never sees letters — it only does math on integers. So first we swap every character for an id.

Char-level (default)

Vocabulary = the sorted set of unique characters in the text — about 65 for Shakespeare. Zero magic.

BPE (optional)

Glues common chunks like the, ing into single tokens, so one token covers several letters.

04 step two

2Embedding — numbers become meaning

An id like 27 is just a label — it carries no meaning. So we look it up in a learned table and get a list of 192 numbers: the token's coordinates in "meaning space."

Vowels drift near vowels, punctuation near punctuation — the model learns this layout during training.

Width = 192  n_embd
every vector in the model lives in this many dimensions 

# a lookup table: id -> 192-dim vector
token_emb = nn.Embedding(vocab, 192)

x = token_emb(idx)   # (B, T, 192)
# B = batch · T = #tokens · C = width

No position table here —
position is added later, cleverly, inside attention.

05 step three · the heart

3The Transformer Block — done 6 times

Two moves per block. Stack six and the model gets six rounds of "look around, then think."

👀

① Attention — look around

Every token gathers information from the earlier tokens that matter to it. This is how context flows.

💭

② Feed-forward — think

Each token, on its own, digests what it just gathered.


x = x + attention(rmsnorm(x))     # look around
x = x + feedforward(rmsnorm(x))   # think

The x + is a residual: keep the original, add the new insight. It's what lets you stack many layers.

model.py · Block
06 attention

Attention, in one sentence

Each token asks a question, every other token offers a label,
and you blend the answers from whoever matches best.

Query

"what am I looking for?"

Key

"what do I offer?"

Value

"what I pass on if picked"


attention = softmax( Q · Kᵀ / √head_dim )   # who to listen to
output    = attention · V                    # the blended answer

07 attention · the rule

"Causal": you can't peek at the future

Predicting the next char, a token may only look at itself and what came before. The upper triangle is blocked.

ROMEO
R1.0····
O.4.6···
M.2.3.5··
E.1.2.3.4·
O.1.3.2.2.2

rows = the token asking  ·  columns = who it listens to

Multi-head: we run this 6× in parallel (n_head=6), so different heads track different things — grammar, quotes, names.
GQA & KV-cache make this cheaper at inference — see the speed slide.

08 position

Where does position come from? RoPE

Attention is order-blind — shuffle the tokens and the math is identical. Something must encode "1st, 2nd, 3rd…".

🧭

The trick: rotate

Spin each token's Query & Key vectors by an angle set by its position — like clock hands. Token 5 rotates more than token 2.

✨

Why it's clever

When two vectors are compared, the result depends only on the difference in angles → the model feels relative distance for free.

No learned position table at all — position is "baked in" by geometry.
model.py · rope_tables · apply_rope  |  RoPE · RMSNorm · SwiGLU = the "2024-era" upgrades over GPT-2
09 step three · part b

3Feed-forward — each token thinks

After attention shares info between tokens, the feed-forward processes each token on its own.

A SwiGLU: one branch does the thinking, a second branch is a gate deciding how much of each signal to let through.


hidden = silu(gate(x)) * up(x)  # gated
out    = down(hidden)
Analogy: the gate is a dimmer switch per idea — turn up what's relevant, dim what isn't, for this specific token.
Flip use_moe=True and this becomes a Mixture of Experts: many feed-forwards + a router that picks 2 per token.

10 step four

4Output — a score for every character

After the 6 blocks, each position holds a rich vector. We turn it back into a guess: one score per possible next char.

Softmax turns scores into probabilities:

next charprobability
e████████ 62%
a███ 18%
o█ 9%
……
🔗Weight tying

The same embedding table that mapped id → vector on the way in is reused to map vector → scores on the way out. One matrix, two jobs — fewer parameters.

11 learning

Training — how it gets good at guessing

1 · Grab textrandom windows; target = input shifted by one
▼
2 · Guesspredict the next char at every position
▼
3 · Measure surprisecross-entropy loss vs. the true char
▼
4 · Nudge weightsbackprop + AdamW lower the loss a little
▼
↻ Repeat 5,000×~7 minutes on a laptop GPU

The only supervision is that one-token shift: "predict what actually came next." That alone teaches grammar, names, and style.

The KV cache — the speed trick

Each layer remembers the Keys/Values it already computed, so generating a new character costs one step over one token — not a re-read of the whole context every time.
